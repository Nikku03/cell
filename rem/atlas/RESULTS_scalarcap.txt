=================================================================================================
THE PER-GENE SCALAR IN THE ENGINE, AND THE CAPS RERUN
=================================================================================================
  genegroups found the context-dependence that damages every compression here is mostly
  ONE OBSERVABLE SCALAR PER GENE, and that sharing classes across groups loses to it. The
  scalar is free in the engine: the observable is the gene's own baseline expression, a
  functional of state the engine already carries, plus one global coefficient.

=================================================================================================
V0  DOES THE SCALAR MOVE THE CAP AT FIXED C? (IN EXECUTED CODE)
=================================================================================================
  genegroups asserted in prose that it does not. block.py's E4 and E7 asserted their
  arithmetic in prose too, were never executed, and were false by a wide margin. So this
  is run rather than argued.

     C classes   cap without scalar   cap WITH scalar   same?
             4                   59                59    True
             8                   30                30    True
            16                   15                15    True
            64                   13                13    True

  V0: PASS -- the scalar changes no cap. It adds one value per gene where the table is a PRODUCT over classes, so it cannot multiply anything.

=================================================================================================

  human MPRA: fit on replicate 1, score on replicate 2, sweep C with and without the
  scalar, and find the smallest C within one noise floor of the finest model -- which is
  signed.py's own criterion, transplanted.

=================================================================================================
V2/V3  THE CAPS, AND WHY THEY DO NOT MOVE
=================================================================================================
  The plan was to take the class count V1 measured on human data, carry it to TRRUST as a
  fraction of the alphabet, and rerun the caps there. V1 CANNOT SUPPLY THAT NUMBER: its
  ladder is narrower than its own noise floor, so the criterion returns C = 1 regardless
  of the truth. Deriving a cap from it would have produced 'human data says C = 3 suffices,
  so the cap is 140 at 71.7% coverage' -- a spectacular claim resting entirely on a
  degenerate statistic. It is withdrawn rather than reported.

  WHAT SURVIVES IS V0, AND IT IS WHAT WAS ASKED FOR. The per-gene scalar is FREE: it adds
  one value per gene where the per-gene factor is a PRODUCT over classes, so it cannot
  multiply anything, and the cap is identical with and without it at every class count
  tested. The caps therefore stand exactly as they were:

    representation                              cap   coverage
    pattern (exact)                               3     12.8%
    class count C = 64                           13     26.6%
    + hub demotion + factored block             140     71.7%
    + per-gene scalar                          unchanged, at whichever row it is added to

  So the scalar is a free ACCURACY gain, not a cap gain, and the class count that sets
  the cap remains the yeast-derived C = 64 -- still unvalidated for human, exactly as
  humantransfer left it. Nothing here changes that, and nothing here pretended to.

=================================================================================================
V4  WHAT THIS DOES AND DOES NOT SETTLE
=================================================================================================
  1. The fraction transfer is an assumption, not a measurement. A class count measured on
     136 motif classes in a reporter assay is being carried to 404 regulators in a
     curated network, and nothing here validates that step.
  2. The scalar is fitted and tested on SINGLE-SITE contexts, because that is all the open
     human data has. Whether one scalar still absorbs the context when several sites are
     present is the copy-number question, still unasked of human data.
  3. V0 is a statement about the COST functional only. It says the scalar is free, not
     that it is sufficient.
