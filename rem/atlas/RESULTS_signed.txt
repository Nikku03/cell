S0  THE CEILING GATE, BOTH HALVES
=================================================================================================
  (a) ACCURACY CEILING. The signed count is given a DELIBERATELY LEAKY sign oracle --
      per-factor effects fitted on all the data, held-out promoters included -- so the
      number below is an upper bound on any honest sign-learning scheme.
      plain count RMSE   1.8960   fallback  2.6%
      SIGNED count RMSE  1.4451   fallback  3.0%   (leaky oracle)
      identity RMSE      1.1641   fallback 11.1%
      the signed count closes 61.6% of the count-to-identity gap
      and leaves 2.41 noise floors open.
      S0(a): FAIL -- REFUTED AT ITS OWN CEILING. The signed count does not reach identity even
      when handed the answer, so no honest sign estimator can make it do so. What follows
      is therefore not a verdict on C = 2 but the curve C = 2 sits on.

      elimination hoisted so every representation is scored on the SAME decomposition.

S4  CAN THE SIGN BE ASSIGNED ON THE REAL NETWORK AT ALL?
=================================================================================================
  TRRUST, 8403 distinct directed pairs after deduplication:
    Unknown           3558   42.3%
    Activation        2927   34.8%
    Repression        1918   22.8%

  42.3% of real regulatory edges carry NO SIGN. A signed count needs one per edge,
  so on this network the representation is not two classes but three -- activator,
  repressor, and unknown -- and the third class is the largest single obstruction to
  using it, before any question of accuracy. This is the same shape of problem as the
  42.3% figure trrust_engine.py had to correct: the annotation, not the method, is the
  limit.

S5  THE ENGINE SIDE, AND WHAT THE SYNTHETIC SYSTEM WAS ACTUALLY TESTING
=================================================================================================
  block.py's generator drives every target by (1+g*b)^(1/nC) with ONE g, so all
  controllers act identically and positively and the drive is a symmetric function of the
  count. The total count was count-sufficient there BY CONSTRUCTION. Three variants:

    nC=4 controllers, nT=5 targets, L=2, dt=0.25; signed relative error on
    the variance of the target count, against the exact joint

    variant                                      total count  signed count  signed diff    pattern
    A  all activators, equal strength              -3.71e-02     -3.71e-02    -3.71e-02   -2.2e-02
    B  half repressors, equal magnitude            -1.77e-01     -2.50e-02    -2.58e-02   -1.9e-02
    C  half repressors, HETEROGENEOUS magnitude     -1.86e-01     -5.93e-02    -6.21e-02   -2.2e-02
    (no conditioning, the baseline that must fail)     -1.98e-01

  Variant A reproduces summary.py: the total count is exact to 3.7e-02, because the system was built that way.
  Variant B: the total count breaks to 1.8e-01 and the
  signed count is exact to 2.5e-02 -- BY CONSTRUCTION,
  since the drive there is a function of the signed difference. That is not evidence.
  Variant C is the informative one. The total count breaks to 1.86e-01; the signed
  count repairs it to 5.93e-02, which is 68.2% of the break.
  On real promoters the signed count closed 61.6% of the
  count-to-identity gap. S5 asks whether those two numbers agree, because if they do not
  the synthetic system is not a model of what promoter.py measured.

=================================================================================================
S6  WHAT THIS DOES AND DOES NOT SETTLE
=================================================================================================
  1. The promoter half tests SITES, not bound factors, at steady state, in two sequence
     contexts, with no time axis. The engine's summary is over controller HISTORY; this
     settles the identity half of that claim and says nothing about the temporal half.
  2. The class map here is fitted from the response itself. That is legitimate for the
     question asked -- is there ANY partition into C classes that suffices -- and it is
     the most generous possible reading of the family. A partition chosen from
     biology alone could only be worse.
  3. The cap is a COST statement from graph arithmetic. It says the engine could be built
     at that size, not that it would be accurate there.
  4. The random class assignment used for the cap is the realistic case, not the best
     one. A class map that happened to align with the network's structure would give a
     higher cap, and one that cut across it a lower.
