=================================================================================================

  GSE37851, sha256[:32] 6a68ee26db7a1d3f4813ae29ed4e69bd. 5790 promoters with at least one site,

S0  THE CEILING GATE, BOTH HALVES
=================================================================================================
  (a) ACCURACY CEILING. The signed count is given a DELIBERATELY LEAKY sign oracle --
      per-factor effects fitted on all the data, held-out promoters included -- so the
      number below is an upper bound on any honest sign-learning scheme.
      plain count RMSE   1.8960   fallback  2.6%
      SIGNED count RMSE  1.4451   fallback  3.0%   (leaky oracle)
      identity RMSE      1.1641   fallback 11.1%
      the signed count closes 61.6% of the count-to-identity gap
      and leaves 2.41 noise floors open.
      S0(a): FAIL -- REFUTED AT ITS OWN CEILING. The signed count does not reach identity even
      when handed the answer, so no honest sign estimator can make it do so. What follows
      is therefore not a verdict on C = 2 but the curve C = 2 sits on.

  (b) COST CEILING. summary.py's cap function with the class-count term added, and the
      elimination hoisted so every representation is scored on the SAME decomposition.

  S1: the smallest C inside one noise floor of identity is 64.
  The signed count (C = 2) is one point on this curve and it is not the knee.
  The C = 404 row is close to identity but not equal to it: classes are fitted IN-FOLD,
  so factors absent from a training fold have no bin and fall together into class 0,
  where the identity model keys on the factor name. That merging is why C = 404 abstains
  slightly less often than identity and scores slightly worse.

  S0's PREDECLARED bar, evaluated: a C counts as a candidate only if its cap beats the
  pattern cap by more than one AND its error is inside one noise floor of identity.
    inside one floor of identity : [64, 128, 404]
    cap beats pattern by > 1     : [1, 2, 3, 4, 6, 8, 12, 16, 32, 64, 128, 404]
    BOTH                         : [64, 128, 404]
  So a candidate exists, and it is C = 64: cap 3 -> 13, coverage 12.8% -> 26.6%. That is a real gain and a modest one. It
  is emphatically NOT the polynomial collapse the total count promised, which was
  cap 419 and 93.3% coverage --
  and which this data refutes. Both ends of the family fail in opposite directions:
  everything cheap enough to keep the 419-controller cap (C <= 4) is
  two or more noise floors from identity, and everything accurate enough to be inside
  one floor has already given back nine tenths of the coverage. What survives is the
  middle, and the middle is worth cap 3 -> 13, not 3 -> 419.

S4  CAN THE SIGN BE ASSIGNED ON THE REAL NETWORK AT ALL?
=================================================================================================
  TRRUST, 8403 distinct directed pairs after deduplication:
    Unknown           3558   42.3%
    Activation        2927   34.8%
    Repression        1918   22.8%

  42.3% of real regulatory edges carry NO SIGN. A signed count needs one per edge,
  so on this network the representation is not two classes but three -- activator,
  repressor, and unknown -- and the third class is the largest single obstruction to
  using it, before any question of accuracy. This is the same shape of problem as the
  42.3% figure trrust_engine.py had to correct: the annotation, not the method, is the
  limit.

S5  THE ENGINE SIDE, AND WHAT THE SYNTHETIC SYSTEM WAS ACTUALLY TESTING
=================================================================================================
  block.py's generator drives every target by (1+g*b)^(1/nC) with ONE g, so all
  controllers act identically and positively and the drive is a symmetric function of the
  count. The total count was count-sufficient there BY CONSTRUCTION. Three variants:

    nC=4 controllers, nT=5 targets, L=2, dt=0.25; signed relative error on
    the variance of the target count, against the exact joint
    Every summary is scored against the FULL PATTERN of the same construction, not
    against zero. The pattern is not exact either -- the product over targets and the
    finite window L, dt both cost something -- so the pattern's own error is the floor
    of this experiment, and a summary's EXCESS over it is the only part that is about
    the summary.

    variant                                       pattern   total count  signed count  signed diff
    A  all activators, equal strength            -2.2e-02     -3.71e-02     -3.71e-02    -3.71e-02
    B  half repressors, equal magnitude          -1.9e-02     -1.77e-01     -2.50e-02    -2.58e-02
    C  half repressors, HETEROGENEOUS magnitude   -2.2e-02     -1.86e-01     -5.93e-02    -6.21e-02
    (no conditioning, the baseline that must fail)                -1.98e-01

    variant                                      total count  signed count   repaired
    excess over the pattern floor, A                1.55e-02      1.55e-02       0.0%
    excess over the pattern floor, B                1.58e-01      5.55e-03      96.5%
    excess over the pattern floor, C                1.64e-01      3.74e-02      77.3%

    the span this is measured on -- no conditioning at all, minus the pattern floor:
      variant A: 2.18e-01   total count uses 92.9% of it, signed count 92.9%
      variant B: 1.68e-01   total count uses 5.9% of it, signed count 96.7%
      variant C: 1.76e-01   total count uses 6.6% of it, signed count 78.8%

  Variant A reproduces summary.py: the total count's excess over the pattern is
  1.6e-02, which is 7.1% of
  the span between the pattern and no conditioning at all -- so the count recovers
  93% of what the full history is worth, because the system was
  built so that the drive is a symmetric function of the count. Not zero, but close.
  Variant B: the total count's excess rises to 1.58e-01 and the
  signed count's is 5.55e-03 -- and that is BY CONSTRUCTION, since
  the drive is a function of the signed difference. Not evidence, and not exactly zero
  either: the drive is a function of the signed difference at each INSTANT, while the
  summary is over a window of L+1 slices, so the construction makes the signed count
  sufficient for the drive and not for the history.
  Variant C is the only informative one. Heterogeneous magnitudes WITHIN each sign class
  are the synthetic analogue of what the promoter data has. The total count's excess is
  1.64e-01, the signed count repairs 77.3% of it.
  On real promoters the signed count closed 61.6% of the
  count-to-identity gap. The synthetic number is 16 points MORE FORGIVING than the measurement, which is the honest way to put it -- the
  two are the same order and the same sign, and the synthetic one flatters the summary.
  The finding is still that the synthetic system only reproduces the measured behaviour
  once it is given repressors AND within-sign heterogeneity. Before that it had neither,
  which is why summary.py's synthetic verdict and promoter.py's measured verdict
  disagreed: they were not testing the same thing.

S6  WHAT THIS DOES AND DOES NOT SETTLE
=================================================================================================
  1. The promoter half tests SITES, not bound factors, at steady state, in two sequence
     contexts, with no time axis. The engine's summary is over controller HISTORY; this
     settles the identity half of that claim and says nothing about the temporal half.
  2. The class map here is fitted from the response itself. That is legitimate for the
     question asked -- is there ANY partition into C classes that suffices -- and it is
     the most generous possible reading of the family. A partition chosen from
     biology alone could only be worse.
  3. The cap is a COST statement from graph arithmetic. It says the engine could be built
     at that size, not that it would be accurate there.
  4. The random class assignment used for the cap is the realistic case, not the best
     one. A class map that happened to align with the network's structure would give a
     higher cap, and one that cut across it a lower.
