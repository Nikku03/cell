THE CLASS COUNT WITH POSITION AND ORIENTATION: AN EXCHANGE RATE
=================================================================================================
  Sharon et al. 2012, doi:10.1038/nbt.2205, GEO GSE37851, sha256[:32] 6a68ee26db7a1d3f4813ae29ed4e69bd.
  5790 promoters, 404 factors, 49 distinct designed start positions in [-1, 113].
  orientation: 10087 plus, 482 minus (4.6% of sites). Noise floor 0.1164 log2.
  position is a live variable for 4903 of 5790 promoters (84.7%):
  that many sit in a (context, factor multiset) group holding more than one layout.
  identity reference: RMSE 1.1641, abstains on 11.1% of held-out promoters.

=================================================================================================
P0(a)  THE COST CEILING: POSITION MULTIPLIES THE ALPHABET
=================================================================================================
  A class count over (factor class x position bin x orientation) has K = C*P*O cells. The
  engine's cost depends only on HOW MANY cells the summary distinguishes, never on what
  makes them distinguishable -- so signed.py's cap curve prices every split already, and
  a position bin costs exactly what a factor class costs.

      budget K = C*P*O  cap |C| at L=8  edge coverage
       pattern (exact)               3         12.8%
                     4             419         93.3%
                     8              25         36.5%
                    16              15         28.6%
                    32              13         26.6%
                    64              13         26.6%
                   128              13         26.6%
  So the question is never 'is position informative'. It is whether a position bin is
  worth more than the factor class it displaces at the same K.

P1  PHASE IS NOT LOCATION -- A PREDICTION, TESTED
=================================================================================================
  Predicted before the test: the paper reports a ~10 bp PERIODIC dependence, V5 tested
  start//10 which is LOCATION, and phase is the feature that should carry what V5 missed.
  Period 7 is the DESIGN LADDER and is here only as the control that tells grid from DNA.

    held out, at a fixed factor-class resolution C = 8 and P = 4 position bins
    position feature                  RMSE    vs P=1   floors  fallback
    none (P = 1)                    1.3419    0.0000     0.00     3.9%
    loc                             1.3430   -0.0011    -0.01     5.2%
    phase                           1.3830   -0.0412    -0.35     6.0%
    phase105                        1.3738   -0.0319    -0.27     5.5%
    ladder                          1.2864   +0.0555    +0.48     4.6%

    the same four on the IDENTITY model, which is what V5 tested:
    none (P = 1)                    1.2140    0.0000     0.00    13.5%
    loc                             1.2678   -0.0537    -0.46    16.5%
    phase                           1.3433   -0.1293    -1.11    18.5%

  P1: the prediction was that PHASE beats LOCATION. Measured: phase 1.3830 against location 1.3430, so the prediction is LOST
  by 0.34 floors, and neither beats P = 1.
  The best feature is 'ladder' -- which is the DESIGN LADDER, the control. Two controls
  now have to say what that is, because without them it is this module's headline.

  CONTROL 1, PERMUTATION. Partition the same 49 start values into 4 bins at random,
  with bin sizes matched to the ladder's. If any partition of position helps this much,
  the 7 bp period is doing nothing.
    24 random partitions: median -0.06 floors, range [-0.26, +0.18]
    the ladder:           +0.48 floors, at the 100th percentile
    So it is not that any partition of position helps. Something about this one does.

  CONTROL 2, RESTRICTION, which is the decisive one. Restrict to the promoters whose
  EVERY site sits on the main ladder. There the ladder feature is CONSTANT and cannot
  contribute, so any position gain that survives is within-ladder and therefore real.
    3184 of 5790 promoters, over 14 designed positions

    within the main ladder, C = 8           RMSE     gain  fallback
    P = 1                                 1.2608     0.00     6.1%
    P = 2, loc                            1.2594    +0.01     7.0%
    P = 4, loc                            1.2992    -0.33     9.2%
    P = 8, loc                            1.3726    -0.96    12.8%
    P = 4, phase                          1.3298    -0.59     9.0%
    P = 4, phase105                       1.3150    -0.47     8.1%

    The gain vanishes. So the ladder's win is BETWEEN design sub-libraries and not
    within one, which makes it design provenance and not a position effect. Without
    this control it would have been reported as this module's positive result.

P5  IS IT THE ESTIMATOR OR THE DATA?
=================================================================================================
  V5 asserted that a group-mean estimator cannot exploit position at this sample size,
  and did not test it. A ridge can use position without splitting groups at all, because
  it shares strength across positions instead of partitioning by them.

    ridge model                                 RMSE  gain vs its own base
    context + class counts (C=8)              1.4206                    --
      + position bins                         1.3554                +0.56f
      + explicit phase (10, 10.5, 7 bp)       1.4034                +0.15f
    context + per-factor counts               1.2199                    --
      + position bins                         1.1568                +0.54f

  and the same two, restricted to the main ladder, where P1's control 2 showed the
  group mean gains nothing:
    class counts, main ladder only            1.3736                    --
      + one term per position                 1.3261                +0.41f
      + helical phase 10, 10.5                1.3606                +0.11f

  A ridge that gains from position where the group mean does not is a statement about
  the ESTIMATOR: the information is there and partitioning is the wrong way to reach it.
  A ridge that gains nothing either is a statement about the DATA at this sample size.

=================================================================================================
P6  WHAT THIS DOES AND DOES NOT SETTLE
=================================================================================================
  1. Position here is a DESIGNED coordinate in a synthetic promoter with at most 49
     distinct values stepping mostly by 7 bp. It is not a dense scan, and a periodicity
     finer than the design step cannot be seen however real it is.
  2. Orientation is 4.6% varied. A null on orientation is an availability result.
  3. The cap is a COST statement from graph arithmetic on TRRUST. It says the engine
     could be built at that size, not that it would be accurate there. And TRRUST has no
     position information at all, so the spatial axis is priced by alphabet size only --
     which is exactly right for the cost and says nothing about whether real regulatory
     positions would cluster helpfully.
  4. The exchange rate measured here is between position and FACTOR IDENTITY at equal
     alphabet. It does not say position is unimportant to a promoter; it says that if you
     have a fixed number of distinguishable cells, this is where they are best spent.
